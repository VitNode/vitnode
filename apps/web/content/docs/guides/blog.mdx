`@vitnode/blog` is the Content Engine reference plugin. It brings articles,
categories, editorial screens, revisions, public delivery data, and search
indexing—without making your host app impersonate a blog plugin.

<Steps>
  <Step>

### Install the package

<Tabs groupId="package-manager" persist items={["bun", "pnpm", "npm"]} label="Install @vitnode/blog">

```bash tab="bun"
bun add @vitnode/blog@canary
```

```bash tab="pnpm"
pnpm add @vitnode/blog@canary
```

```bash tab="npm"
npm install @vitnode/blog@canary
```

</Tabs>

  </Step>
  <Step>

### Register the plugin

One line in `src/vitnode.config.ts` enables everything the plugin ships - its
API modules, its AdminCP screens and its content types. A Single App and a
split deployment use the same line; in a split deployment both the web app and
the API app carry it, and each loads only its own half.

```ts title="src/vitnode.config.ts"
import { blogPlugin } from '@vitnode/blog/config' // [!code ++]

export default defineVitNodeConfig({
  plugins: [
    blogPlugin(), // [!code ++]
  ],
})
```

Tune it with typed options; the plugin validates them for you:

```ts
plugins: [
  blogPlugin({
    postsPerPage: 12,
  }),
]
```

  </Step>
  <Step>

### Register its messages

Add the plugin's locale files to `src/locales/packages.ts`, which the web
runtime's `server` factory loads:

```ts title="src/locales/packages.ts"
import { CONFIG_PLUGIN as BLOG } from '@vitnode/blog/const' // [!code ++]

export const packageMessages = {
  // [!code ++:3]
  [BLOG.pluginId]: {
    en: async () => await import('@vitnode/blog/locales/en.json'),
  },
}
```

  </Step>
  <Step>

### Migrate, run, and publish

<Tabs groupId="package-manager" persist items={["bun", "pnpm", "npm"]} label="Prepare and start the blog">

```bash tab="bun"
bun run db:migrate
bun dev
```

```bash tab="pnpm"
pnpm db:migrate
pnpm dev
```

```bash tab="npm"
npm run db:migrate
npm run dev
```

</Tabs>

In AdminCP, create a category at **Blog → Categories**, then publish an article
at **Blog → Articles**. The plugin owns the editorial work so the host can stay
boringly reliable.
